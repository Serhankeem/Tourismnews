## 3. 공개 발행 계약 — 설계안, 미구현

`public-content.schema.json`은 제안된 JSON Schema입니다. 실제 공개 데이터 파일이나 승인된 콘텐츠 인스턴스를 생성하지 않았습니다. 원장/비공개 진단 JSON을 복사하는 방식이 아닙니다.

| 계층 | 내용·보관 | 다음 단계 조건 |
| --- | --- | --- |
| 비공개 원본/진단 | 원자료, 입력 스냅샷, 전체 빈티지, 내부 해시/승인 정보 | 엔진의 적격성·승인 범위·비교 검증 |
| 편집 검토 완료 원고 | 동결된 제목/요약/근거/주의사항, revision 및 원고 해시; 비공개 유지 | 지정 편집자의 식별자·시각·체크리스트·동일 해시에 대한 검토 기록 |
| 게시 승인 공개 콘텐츠 | 허용 목록으로 투영한 최소 필드만 | 별도 게시 담당자의 동일 해시·편집 기록 참조·대상월·revision·유효기간·범위 확인 |
| 과거 발행본/정정본 | 승인된 각 발행본의 불변 스냅샷과 정정 연결 | 정정 사유·이전 revision·재검토/재승인; 예전 발행본 보존 |

공개 구조는 content_id/revision, 기준월/자료 마감/실제 발행시각, 제목/요약, 두 핵심 원값·단위·MoM/YoY와 비교월, 최대 3개 근거·공식 출처, 필수 한계, 방법론 및 정정 연결입니다. 각 비교에는 반올림된 비율과 별도로 원값에 따른 정확한 direction을 둡니다. 표시가 0이더라도 임의로 보합으로 바꾸지 않습니다. 신규 ECOS·항공·기타 지표, 비공개 입력 해시·파일 경로·키·전체 진단·개인 검토자 정보는 포함하지 않습니다. 원공표일은 미확인 null을 허용하며 원공표일을 만들지 않습니다. 현재 모델은 `overall_state=withheld`, `analysis_mode=retrospective_current_vintage`로 제한합니다.

**단일 플래그로 공개할 수 없습니다.** 제안된 공개 스키마에는 `publication_approved`를 넣지 않았습니다. 비공개 진단 및 그 플래그만 바꾼 문서는 스키마에서 거절됩니다. 그러나 스키마는 형태 검사일 뿐 승인 권한 검증이 아닙니다. 아래 서버 측 과정이 별도 구현·심사되기 전 공개 경로를 열지 않습니다.

1. 동결 원고와 사실 근거를 바인딩한 콘텐츠 해시를 생성. 원고/수치/출처/비교월/한계 중 하나라도 바뀌면 기존 확인을 무효화.
2. 편집자의 원고 해시·revision·대상월·검토시각·항목별 확인을 담는 비공개 검토 영수증. 제출 문서가 주장하는 이름 대신 신뢰된 인증 경로의 사용자 식별자로 확인.
3. 별도 게시 승인 영수증은 같은 원고 해시와 편집 영수증 해시, 정확한 대상월/판본, 게시 범위·유효기간을 바인딩. 두 결정이 같은 사람에게 배정되더라도 서로 다른 명시적 의사 결정으로 기록.
4. 게시 시점에 실제 승인 권한·만료·철회 상태와 원통계의 기존 수집/게시 범위를 재검사. 원통계 승인만으로 파생 원고를 승인하지 않음. 이미 확인된 원통계 이용조건은 유지하며 출처 표시를 반영.
5. 원값/단위/목표월·MoM/YoY 비교월/독립 계산/출처 ID 참조/권리 범위의 의미 검증. JSON Schema가 숫자의 진실성이나 편집 문구의 의미를 보장하지 않음.
6. 별도 allowlist 투영으로만 공개 콘텐츠 생성. 원본 JSON을 수정/이름 변경/일부 필드 제거해 게시하지 않음. 영수증/키/내부 승인 기록은 공개 JSON에 넣지 않음.
7. 조립 전·업로드 전 권한/해시를 다시 확인하고 공개 카탈로그와 발행본을 일관되게 갱신. 불일치·누락 시 이전 승인 발행본 유지 또는 미공개 상태, 자동 보충 없음.

검토/게시 담당자 지정, 권한 확인 경로와 영수증 보관 방식, 유효기간·철회 정책은 사용자가 결정해야 합니다. **검증기·게시 투영기·승인 영수증 발급기·자동 발행은 이번에 구현하지 않았습니다.** 현재 Preview 공개 모드는 그대로 닫혀 있습니다.

## 4. 사이트 통합 구조 — 구현하지 않은 후속 계획

- **`#weather` 메인:** 승인된 최신 월간 부분 모니터를 우선 배치. 승인본이 없으면 명시적 미공개 상태와 별도 시뮬레이터 진입만 제공. 비공개/Preview 결과로 대체하지 않음.
- **과거 월간:** 기준월과 revision을 선택해 당시 승인된 불변 발행본을 열람. 현재 Macro 값으로 과거 발행본을 재계산하지 않음. 정정 사유·이전본 링크·발행/정정 시각 구분.
- **Macro 상세:** 원지표별 `#macro`로 연결하고 기준월을 설명. Macro 최신 기준월이 과거 원고와 다를 수 있음을 표시. 필요한 경우 허용된 두 지표만 선택/초점을 이동하는 후속 연결.
- **시뮬레이터:** `#weather-simulator` 같은 별도 진입을 명시적으로 추가하는 안. 현재 `navigate()`는 미등록 해시를 overview로 돌리므로 alias/subview 처리가 필요함. 기존 단일 DOM·슬라이더 ID·reset·키보드·계산식·점수·입력 초기값은 유지하고 월간 통계와 바인딩하지 않음. 기존 `#weather` 진입/뒤로 가기/앞으로 가기 호환을 별도 검수.
- **모바일/접근성:** 월간/과거/시뮬레이터의 명확한 텍스트 탐색, 제목/초점 이동, 현재 선택 ARIA, 링크 목적, 접기/표의 키보드 동작, 축/단위 설명 및 320px/확대/스크린리더 수동 검수. 종합 판정 보류를 색이나 아이콘만으로 전달하지 않음.
- **홈의 기존 날씨 영역:** 기존 가정 점수를 실측 시장 상태로 오인하게 연결하지 않도록 시뮬레이터 표시·진입 의미를 별도 검토. 이번에는 변경하지 않음.

## 5. 제출 범위

실제 수치·편집 작업본·체크리스트 상태는 Git 밖에 보존합니다. 저장소에는 두 구형 스모크의 최소 수정, 값 없는 심사/통합 문서, 제안 스키마와 검증 요약만 제출합니다. `site/`, `src/`, `preview/`, 운영 `data/live`, 621개 관측, TOURGO 승인·워크플로는 그대로입니다. 새 통계 활성화·게시 승인·Actions 운영 실행·자동 발행·PR 병합·Production 배포는 없습니다.
