# Step 19 — 홈페이지 통합 및 비공개 발행 리허설

기준 main은 PR #58 병합 커밋 `62550a6ddc6f8cda5b89032afd565da056e51698`입니다. **첫 월간 콘텐츠의 게시 승인·발행·배포를 수행하는 변경이 아닙니다.** 실제 r2 원고, 승인 기록, 신뢰 정책, 진단 결과 및 운영 수치를 이 문서나 공개 저장소에 추가하지 않습니다.

## 홈페이지와 데이터 경계

- `#weather`: 월간 진단 reader. 승인된 쌍이 없으면 `아직 발행된 월간 진단 없음`만 표시합니다. 운영 Macro 수치를 월간 원고로 자동 전환하거나 0/예시값으로 보충하지 않습니다.
- `#weather-simulator`: 기존 시나리오 입력·초기화·계산식·공식 관측 차트의 별도 진입점입니다. 기존 DOM ID와 계산은 유지합니다. 홈 시나리오 CTA와 공식 관측 상세 링크는 이 경로로 연결합니다.
- 월간 reader는 제목, 기준월/편집·공개 판본, 두 관측/비교율, 동결된 다섯 본문 섹션, 공식 출처·한계·마감/회고 방식, Macro Monitor 링크를 표시합니다. 첫 공개판본만 지원하며 산업 활동 부재에 따른 종합 판정 보류를 유지합니다. 원고 문장을 다시 생성하지 않습니다.
- 원문 Markdown은 허용한 강조·문단·목록·공식 HTTPS 링크만 DOM으로 표시하며 HTML을 삽입하지 않습니다. 명목 US$와 명 단위를 유지합니다. 비교율은 BigInt로 반올림하고 비교값 부재는 `비교 불가`입니다.

공개 경로 두 개는 **승인된 발행 요청이 생길 때만** 활성화하는 선택 allowlist입니다.

| 경로 | 내용 |
| --- | --- |
| `site/data/market_weather_index.json` | 공개판본 목록·latest·콘텐츠 SHA-256·노출 유효기한 |
| `site/data/market_weather_archive.json` | Step 18 공개 v2 최소 계약의 콘텐츠 객체들 |

현재 이 두 파일은 main/이 브랜치의 `site/data`에 없으며 실제 r2 파일도 생성하지 않습니다. `pipeline.json`에는 파일명 허용 목록만 추가합니다. 원고·입력 원장·핀·개인 식별 승인 기록은 이 쌍에 들어가지 않습니다. 브라우저의 해시/계약 검사는 잘못된 파일 조합을 거절하는 보조 검사이며 게시 권한 인증을 대신하지 않습니다.

## 보호된 발행 경계

`src/macro/weather_release.py`는 기존 `weather_publication.public_json()`을 재사용합니다. 별도 편집/게시 승인·역할 핀·철회·유효기간, 정확한 원고/편집 기록/입력/공개 계약/투영 구현 해시, 현행 통계 권리와 TOURGO 기간을 매번 검사합니다. `approved=true` 문자열이나 공개 JSON에서 신뢰를 얻지 않습니다. 실제 원고에서 게시 승인이 없으면 투영/직렬화 **이전**에 거절합니다.

운영자가 보호된 런타임에 저장소 밖 읽기 전용 디렉터리를 공급할 때만 `directory()`를 사용합니다. 디렉터리에는 읽기 전용 `authority.json`이 있으며 정확한 구조는 다음과 같습니다. 아래 경로는 자리표시자이고 승인 기록의 예시를 발급하는 것이 아닙니다.

```json
{
  "version": 1,
  "trust_policy": "/operator/private/readonly-trust.json",
  "records": [
    {
      "editorial_record": "/operator/private/editorial-approval-record.json",
      "publication_record": null
    }
  ]
}
```

`null`은 게시 승인 부재이며 발행 거절입니다. 승인자가 별도로 결정한 게시 기록과 운영자가 별도 검증해 설치한 publication 핀 없이는 이를 해소하지 않습니다. trust 파일도 저장소 밖 읽기 전용이어야 합니다. 원고 경로는 편집 핀 인증 후에만 읽습니다. 새 registry/핀을 Git/사이트/업로드 아티팩트에 넣지 않습니다. 파일 권한은 OS 관리자를 방어하는 서명 서비스가 아닙니다. 공급·갱신·철회 책임과 인증된 전달 경로는 운영자가 정해야 합니다.

기존 main 전용 `src.pipeline.runner`에 선택 인자 `--monthly-authority-dir`와 `--monthly-release-key`를 추가합니다. 기존 보호된 실행 맥락 검사와 Git fast-forward 트랜잭션을 그대로 거치며 신규 워크플로나 스케줄러를 만들지 않습니다. 이 문서는 지금 실행할 운영 명령을 제공하지 않습니다. 게시·배포 승인 후 보호된 운영자가 정확한 공개판본 키를 명시해야 최초 발행 요청이 만들어집니다. 디렉터리를 제공하는 것만으로 새 판본을 자동 발행하지 않습니다.

이미 발행 파일이 있는 정기/코드 배포 트랜잭션도 `MARKET_WEATHER_AUTHORITY_DIR` 또는 같은 CLI 인자를 통해 **새로 읽은** 신뢰 기록을 제공해야 합니다. 운영 공급 경로는 아직 설치하지 않았습니다. 미공급·철회·만료·해시 불일치는 다음 발행/조립/업로드를 차단합니다. 기존 워크플로에 신뢰 파일을 복사하거나 실제 실행하지 않았습니다.

### 단계별 보존과 거절

1. 복구한 data/live 스냅샷의 checksum·inventory·정합성을 검증합니다. 두 선택 파일은 동시 존재해야 하며 일반 collector가 생성/변경하면 그 collector의 변경을 롤백합니다.
2. 발행 요청은 모든 Gate 검사를 통과한 후 **격리된 transaction stage에만** 쌍을 씁니다. 기존 판본 삭제/변경·잘못된 latest/중복/카탈로그 불일치를 거절합니다. 동일 내용의 반복 발행은 byte-identical no-op입니다. 이전 공개판본을 덮어쓰는 정정 발행은 지원하지 않습니다.
3. 원장 검증과 Gate 재검사 후 기존 Store가 정상 fast-forward로 저장합니다. 저장 전 및 push 직전에도 현재 승인/철회를 다시 확인합니다. 실패한 발행은 운영 ref를 갱신하지 않습니다.
4. Pages는 data/live의 공개 allowlist와 `static_public_files`만 조립합니다. 비공개 원장·임의 JSON/Markdown/추가 정적 파일·symlink를 거절합니다. 조립 후 Gate/복사 해시를 다시 확인하고 완성된 디렉터리를 교체합니다. 실패 시 이전 산출물을 보존합니다.
5. 기존 upload guard는 최신 main/data 커밋·정책 평가일뿐 아니라 복구 snapshot, 현재 승인/권리, **전체 산출물 파일 목록과 해시**를 재검사합니다. 조립 후 private 파일 추가/수치 변경도 거절합니다.

프로세스의 검사 직후 외부 정책이 바뀔 수 있는 시간 차이와 이미 배포된 정적 파일 회수는 별도 운영 문제입니다. 철회는 새 발행/배포 거절이며 이미 공개된 bytes를 원격 삭제하거나 비공개로 되돌리는 기능이 아닙니다. reader는 재진입 시 만료를 확인하지만 실시간 철회 감시를 하지 않습니다. 공개 철회가 필요하면 명시적인 콘텐츠 회수·카탈로그 갱신·캐시 확인/배포 절차를 별도로 승인해야 합니다. Gate와 카탈로그가 첫 판본만 지원하므로 정정·회수 정책은 후속 과업입니다.

## 리허설과 실제 r2의 차이

```sh
python -m tools.market_weather_rehearsal \
  --snapshot /absolute/private/readonly-data-snapshot \
  --work /absolute/private/new-rehearsal-directory
```

이 개발 도구는 네트워크/원격 Git/Actions를 사용하지 않습니다. 기존 Gate 테스트의 명시적 **합성 원고·수치·승인**만 이용해 격리 stage와 합성 Pages, 미발행 Pages를 만듭니다. `--work`는 저장소와 입력 snapshot 밖의 새 디렉터리여야 합니다. 원본 snapshot의 전체 파일 해시를 전후 대조합니다. 원본에는 기존 권리 투영 검사를 통과하는 검증 snapshot을 사용해야 합니다. 실제 원고/승인을 받아 발행하는 인자는 없습니다. 합성 승인 핀을 운영에 옮기면 안 됩니다.

실제 r2는 기존 편집 승인 및 원고 해시를 재검증하고, 게시 기록 없이 `PublicationRequest.apply()`를 호출하여 **투영 함수가 호출되지 않고 stage가 그대로인지** 검사했습니다. 결과는 `publication_approval_missing`, 실제 공개 JSON **0개**입니다. 독립 XLSX 재파싱·역사적 as-of 빈티지 미검증 등 기존 한계도 유지합니다. 실제 내용 검토에는 기존 보호된 로컬 Preview를 사용하며 공개 reader로 복사하지 않습니다.

- 기존 공개 사이트/홈/헤더·내비게이션/시뮬레이터/Macro/뉴스/Daily Briefing/리서치 및 기존 private Preview·Gate/Python 회귀를 유지합니다. 기존 스모크 테스트의 내비게이션 경로/라벨과 TOURGO 활성 상태 선행조건만 현재 계약에 맞춥니다.

자동 접근성 검사는 실제 스크린리더와 최종 사람 검수를 대체하지 않습니다. 합성 로컬 리허설이 Production 발행·배포 성공을 입증하지 않습니다. 실제 r2·스크린샷·핀·감사 기록은 Git 밖 격리 디렉터리에 보존합니다.

## 게시/배포 전에 필요한 별도 결정

1. 원고·입력·현재 권리·변환 방식/공개 화면의 사람 최종 검수. 기존 TOURGO **2021-01~2026-09**, 비상업·무료·광고 없음·출처표시 범위를 유지합니다.
2. 정확한 해시/편집 기록/계약/구현·공개판본·발행 기준시각·범위·기한을 특정한 **별도 게시 승인**과 외부 신뢰 핀 설치. 현재 게시 승인은 없습니다.
3. 보호된 실행 환경에서의 읽기 전용 authority 공급·권한·철회 책임과 최초 수동 발행/이후 재검증 절차 승인. 새 계열·새 기간을 포함하지 않습니다.
4. Draft PR 사람 검수와 별도 코드 병합/Production 배포 승인. 기존 main push가 자동 배포를 유발하므로 승인 전 병합하지 않습니다.
5. 정정·철회/만료 후 공개물 처리, 운영 모니터링, 캐시/접근성 및 첫 공개 화면의 확인 책임 지정.

### 롤백

현재 단계에서는 PR을 병합하지 않으면 운영 영향이 없습니다. 통합 코드 배포 후 UI 문제가 있으면 별도 승인 아래 해당 **코드 변경만** 되돌려 기존 시뮬레이터 진입을 복구합니다. data/live 전체를 과거로 되돌려 최신 뉴스·리서치·Macro를 잃게 하면 안 됩니다. 발행 전 실패는 기존 산출물/공개판본을 그대로 보존합니다. 발행 후 콘텐츠 회수는 자동 롤백으로 간주하지 말고 별도 회수 승인·카탈로그 계약/구현 검토가 필요합니다. 비공개 원고·입력·승인/감사 이력은 변경 없이 보존합니다.
