# Market Weather: 검수 후 1회 승인 발행

이 패치는 main `0691aec5` 기준입니다. 기존 Deploy → 공유 pipeline → data/live 트랜잭션 → Pages guard 경로를 사용합니다. 새 workflow·DB·서비스·비공개 저장소를 만들지 않습니다. 이 문서는 발행 승인이 아니며 이 PR에서는 실제 승인/발행/운영 실행을 하지 않습니다.

## 변경한 경계

1. 오프라인 도구가 원고와 기존 동결 입력을 검증하고, Git 밖에 비공개 `candidate.b64`와 `review.json`을 만듭니다. 원본 전체 bundle의 파일 해시도 먼저 검사합니다. 전달 파일에는 원고와 재검산에 필요한 원본 바이트만 들어가며 과거 민감도 보고서 전체는 재전달하지 않습니다.
2. 검토자는 원고·수치·미검증 한계를 확인하고 **기존 Deploy의 Run workflow에서 원고와 candidate SHA-256 두 개를 지정하는 한 번의 동작으로 발행을 승인**합니다. 월별 편집/게시 이중 영수증 및 외부 Trust pin은 이 경로에 필요하지 않습니다. r2의 옛 승인을 r3로 승계하는 방식도 아닙니다.
3. 실제 GitHub API의 실행 경로·main/head SHA·수동 이벤트·실행 제목(두 해시)·실행자 ID·저장소 소유자 ID 일치을 확인합니다. 첫 실행만 허용하며 재실행은 새 수동 dispatch가 필요합니다. 임의의 `approved=true` 환경변수나 로컬 파일만으로 승인할 수 없습니다. API 불가/403/실행 정보 불일치는 차단합니다.
4. 기존 숫자/Decimal/비교월/출처/통계 정의·기간/권리/동결 빈티지 검증을 재사용한 뒤에만 최소 공개 데이터를 투영합니다. 새 입력 해시는 원고뿐 아니라 동결 통계·진단·manifest 전체를 묶으므로 통계 입력만 교체해도 차단됩니다.
5. 발행된 카탈로그 두 파일 전체에 HMAC-SHA256 `seal`을 남깁니다. 이후 RSS/Research/Macro/일반 Deploy는 **고정 서명 Secret 하나**로 변조 여부를 확인하고 현행 권리와 승인 범위를 재검사합니다. 원고·영수증·Trust·검토자 정보 재전달이 필요 없습니다. 공개 reader에는 signature 한 필드만 추가 허용하며 공개 콘텐츠 계약과 표시 함수는 유지합니다. 브라우저는 서명 권한을 부여하지 않으며 서버의 Pages gate가 서명을 검증합니다.

기존 이중 승인 API는 과거 테스트/자료 호환용으로 보존합니다. unsigned 기존 카탈로그는 종전 Authority 없이는 통과하지 않으며 자동으로 서명해 주지 않습니다. 아직 실제 발행물은 0건이므로 VOL.01에 마이그레이션할 공개 파일은 없습니다. 기존 발행본은 불변이며 같은 판본의 다른 내용으로 재발행할 수 없습니다. 같은 내용을 재시도하면 기존 파일 바이트를 유지합니다.

`not_after=9999-12-31T23:59:59+00:00`은 기존 reader 형식을 유지하면서 발행 아카이브가 매월 자동 만료하지 않게 하는 표현입니다. 자료 이용허락을 영구화하지 않습니다. 운영 권리 철회/만료·기간/정의 변경은 배포 때 계속 검사하며 차단됩니다. 과거 공개 수치는 당시 동결 빈티지이므로 현재 정정된 원장값으로 덮어쓰지 않습니다.

## 최초 필수 설정 — 아직 수행하지 않음

저장소 **Actions repository Secrets**에 다음 두 개를 설정합니다. 운영 Secret 값을 채팅·로그·공개 문서에 적지 않습니다.

| Secret | 설정 및 수명 |
| --- | --- |
| `MARKET_WEATHER_SIGNING_KEY` | 암호학적 난수 32바이트의 소문자 hex 64자리. 최초 1회 생성하고 안전하게 백업. 이후 정기 수집/배포도 같은 키를 사용하므로 매호 교체하거나 삭제하지 않습니다. 키 유실/교체는 기존 발행본 검증을 차단하므로 별도 검수된 복구가 필요합니다. |
| `MARKET_WEATHER_CANDIDATE_B64` | 준비 도구가 생성한 파일 내용. 이번 파일은 Secret의 48 KiB 제한 이내입니다. 매호 제작 과정에서 갱신하며 사용자 승인 대상 두 해시와 일치해야 합니다. 일반 정기 실행에는 후보 Secret을 주입하지 않습니다. |

공유 pipeline은 실제 실행 조회를 위해 `actions: read`를 사용하며 기존 호출 workflow에도 이 읽기 권한만 추가합니다. 기존 쓰기 권한·공유 lock·수집 엔진·Pages 저장/검증/롤백 경로는 그대로입니다. 권한 API가 GitHub runner에서 접근 불가하면 실패하며 대체 문자열로 통과시키지 않습니다. 실제 인증 Actions는 이번에 실행하지 않았으므로 그 운영 검증은 남아 있습니다.

Secret 등록은 한 번의 환경 준비이며 게시 승인이 아닙니다. 이후 매호 **원고 제작/자동 검수/후보 전달 → 사용자 Run workflow 승인 한 번 → 기존 자동 저장·배포** 순서입니다. 별도 편집 pin·게시 pin·Authority 디렉터리를 관리하지 않습니다. 현재 범위 밖의 새 통계월은 원자료의 별도 수집·게시 적격성을 갖춰야 하며 콘텐츠 승인이 이를 확대하지 않습니다.

## 운영자 절차 — 병합·발행을 별도 허가하기 전 실행 금지

1. Draft PR과 테스트·원고·기존 Preview를 검수합니다. 사용자 허가 후 패치를 main에 병합합니다. 병합 자체는 코드 배포를 유발하지만 후보를 발행하지 않습니다(해시 입력 없는 push는 콘텐츠 승인 아님).
2. 위 Secret 두 개를 보안 설정에 전달합니다. 예를 들어 권한 있는 운영자가 `gh secret set MARKET_WEATHER_CANDIDATE_B64 --repo Serhankeem/tourismnews < /보안경로/candidate.b64`로 파일 내용을 전달할 수 있습니다. 키는 안전하게 생성한 파일에서 같은 방식으로 최초 등록합니다. 이 과업에서는 Secret을 생성·등록·변경하지 않았습니다.
3. GitHub Actions → **Deploy latest code with durable data** → **Run workflow**, branch **main**을 선택합니다. `monthly_manuscript_sha256`과 `monthly_candidate_sha256`에 위 검수 결과의 두 해시를 정확히 입력합니다. **Run workflow가 해당 판본에 대한 명시적 발행 승인**입니다. 통상 코드 배포는 두 입력을 모두 비웁니다.
4. GitHub 실행 정보에서 확인한 저장소 소유자에 대해 자동 검증·기존 트랜잭션 저장·Pages guard·배포를 수행합니다. 큐 대기 중 main이 바뀌었으면 차단하므로 최신 코드 검수 후 새 dispatch로 승인합니다. 임의 재실행으로 승인을 재사용하지 않습니다.
5. GitHub Pages 배포 성공과 실제 URL, code/data commit, 파일 해시를 확인해야 실제 발행 완료입니다. `issued_at`은 승인된 dispatch 기준시각이며 배포 완료 증거가 아닙니다. 배포 실패 시 기존 공개 사이트가 유지되고 다음 정상 배포는 이미 저장된 서명본을 검증할 수 있습니다. data/live 전체 초기화/강제 롤백은 하지 않습니다.

## 검증 범위

합성 실행/합성 기사만으로 정상 승인, 미승인·다른 workflow·다른 SHA/실행자·재실행 차단, API 실패, 통계/원고 변조, 권리 철회, 서명/키 오류, 기존 발행본 보존·중복 방지, 실제 bare Git 저장 후 RSS 갱신/Pages 조립을 검사합니다. 공개 reader는 합성 서명본으로 네 화면 크기·키보드·axe 검사를 수행합니다. 실제 VOL.01에는 오프라인 자동 검수만 수행하고 공개 투영을 하지 않습니다. 기존 전체 Python 회귀를 함께 실행합니다.

검증 기록: 최초 전체 Python 779개 통과 후 저장 시도마다 후보 해시를 다시 검증하는 테스트를 보강했고 해당 15개 검사가 통과했습니다. 최종 전체 회귀는 PR CI에서도 재확인합니다. 합성 서명본의 Playwright 네 화면 크기·키보드·axe 자동 위반 0개입니다. actionlint 1.7.11은 기존 `concurrency.queue: max` 문법을 아직 인식하지 못하므로 그 기존 항목만 제외하면 변경한 모든 workflow 검사가 통과합니다. 기존 큐 정책은 수정하지 않았습니다.

후속 authorization 보강은 [실패 Run 분석 및 수정 기록](market-weather-authorization-fix.md)을 참고합니다. collaborator 역할 조회를 추가 토큰 없이 실행 정보의 소유자 대조로 대체했으며, 기존 실패의 정확한 내부 원인은 당시 진단에서 보존되지 않았습니다.
